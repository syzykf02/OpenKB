# 法宝法律智能知识库 - 界面集成方案

## 概述

本文档说明如何在现有 OpenKB 界面基础上集成法律知识库功能。

---

## 一、现有界面结构分析

### 1.1 主要页面

- **Home** (`/`) - 首页
- **ChatSession** (`/chat/:id`) - 对话页面
- **KbList** (`/kb`) - 知识库列表
- **KbDetail** (`/kb/:id`) - 知识库详情（主页面）
- **Settings** (`/settings`) - 设置页面

### 1.2 KbDetail 页面布局

```
┌─────────────────────────────────────────────────────────────┐
│  🏠  OpenKB  |  [侧边栏切换]  [知识库面包屑]              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌───────────────────────────────────────────────────────┐ │
│  │  📊 Index  📑 Summaries  💡 Concepts  👤 Entities  │ │
│  │  Reports  ────────────────────────────────────────────│ │
│  └───────────────────────────────────────────────────────┘ │
│                                                             │
│  [ 主内容区，根据选中卡片切换 ]                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 七、API 扩展设计

### 7.1 法律知识图谱 API

```typescript
// openkb/legal/api_graph.py

// 获取图谱节点
GET /api/v1/legal/graph/nodes
  返回: { nodes: GraphNode[], total: number }

// 获取单个节点
GET /api/v1/legal/graph/nodes/{nodeId}
  返回: GraphNode

// 获取关联节点
GET /api/v1/legal/graph/nodes/{nodeId}/related
  查询: relationType (可选), depth (默认 2)
  返回: { related: TraversalResult[] }

// 影响分析
GET /api/v1/legal/graph/nodes/{nodeId}/impact
  返回: { affected: TraversalResult[], summary: string }

// 检测矛盾
GET /api/v1/legal/graph/contradictions
  返回: { contradictions: [node1, node2, edges][] }
```

### 7.2 同步引擎 API

```typescript
// openkb/sync/api_sync.py

// 列出同步源
GET /api/v1/legal/sync/sources
  返回: { sources: SyncSource[] }

POST /api/v1/legal/sync/sources
  数据: AddSyncSourceForm

// 扫描差异

  返回: { scanDiff: DiffResult, manifest: FileManifestEntry[] }

POST /api/v1/legal/sync/sources/{sourceId}/sync
  SSE 流式返回进度
```

## 九、总结

本方案在现有 OpenKB 界面基础上，**渐进式地扩展**法律知识库功能：

1. **扩展而非替换** - 保留现有功能，添加新的法律专业卡片和功能
2. **模块化设计** - 新增组件独立，易于维护和测试
3. **用户友好** - 遵循现有设计语言，保持一致性
4. [ ] 按需视觉分析 - 视觉工具只在需要时触发，节省成本
5. [ ] 法律专业优化 - 文档结构、证据包等针对法律场景优化
